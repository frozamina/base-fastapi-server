# 如何加模块

新业务放在 `app/modules/<模块名>/`，不要写进 `core`。一个模块通常有这些文件：

- `models.py`：表。继承 `IntIdTableModel` 或 `AuditTableModel`。关联只用普通字段加索引，不建物理外键。
- `schemas.py`：请求和响应，请求体继承 `RequestModel`。
- `repository.py`：只做查询和落库，继承 `BaseDAO`。
- `service.py`：业务规则和 `commit`，继承 `BaseService`。
- `router.py`：HTTP。写操作通过 `service_dep` 拿服务。

下面用「公告」举例。基项目本身没有这个模块。

`app/modules/notice/router.py`：

```python
from fastapi import APIRouter, Depends

from app.core.security.deps import module_guard
from app.shared.deps import service_dep
from app.modules.notice.service import NoticeService

router = APIRouter(dependencies=[Depends(module_guard("notice"))])
```

`module_guard("notice")` 会按请求方法检查 `notice:read`、`notice:write`、`notice:delete`。权限码 `*` 视为全部通过。

然后做三处登记：

1. 在 `app/modules/system/seed.py` 的 `PERMISSIONS` 里加上这三项，并决定哪些角色拥有它们。
2. 在 `app/core/database/registry.py` 的 `import_models` 里导入 `app.modules.notice.models`，否则 `create_all` 看不到新表。
3. 在 `app/main.py` 里 `include_router`，前缀例如 `/api/notices`。

对应的建表语句追加到 `ddl/`，命名按序号，例如 `ddl/002_notice.sql`。启动时的 `create_all` 只建缺的表，不会改已经存在的列，所以已上线的结构变更要写 SQL。

删除用 `is_deleted`，不要物理删除。校验关联记录是否存在，写在该模块的 service 里。
